# BE2 POD Status Audit

Source baseline: `feature/printing`, HEAD `fc3ade5`, 25 October 2026. The working tree already contained uncommitted Staff Review and Quote/Production code when this audit began; no BE1 source, SecurityConfig or schema was changed here. BE2 has 36 source-mapped Model/Printing controller routes. PostgreSQL V2 runtime and generated OpenAPI are not verified.

## Status writers

| Field | Writer and trigger | Preconditions / concurrency | History and replay |
| --- | --- | --- | --- |
| `print_requests.status`, `submitted_at` | `PrintRequestStateService.submit` -> `PrintRequest.submit`: initial or corrected submission | CUSTOMER owner, `findOwnedByIdForUpdate`, current File/Spec, rights, preview, material/source validation; transaction | `DRAFT/REQUIRES_REVISION -> SUBMITTED` inserted with actor. Repeated Submit conflicts. |
| `print_requests.status` | `PrintRequestTechnicalReviewService.requestCorrection` -> `PrintRequest.requireRevision`: Staff correction | Staff/Admin controller, `findByIdForUpdate`, expected current pair, no quote/lock; transaction | `SUBMITTED -> REQUIRES_REVISION` inserted. Same-pair repeated review conflicts. |
| `print_requests.status`, `current_quote_id`, `handled_*` | `PrintRequestQuoteService.issueQuote` -> `markQuoted`: first/replacement quote | Staff/Admin route, request lock, version-bound approval, immutable item snapshot, original deadline; transaction | `SUBMITTED -> QUOTED` inserted; quote reissue does not insert same-status history. |
| `print_requests.status` | `PrintRequestQuoteService.acceptQuote` -> `markQuoteAccepted`: Buyer accepts current quote | CUSTOMER owner, request lock, exact current quote/pair, before fixed deadline, 100% upfront; transaction | `QUOTED -> QUOTE_ACCEPTED` inserted; replay conflicts. |
| `print_requests.status`, `cancelled_at` | `PrintRequestStateService.cancel`: customer cancellation | CUSTOMER owner, request lock, workflow policy, no current quote/production lock; transaction | Eligible state -> `CANCELLED` inserted; replay conflicts. |
| `print_requests.status`, `cancelled_at` | `PrintRequestQuoteService.expireIfOverdue` or request-time expiration: unaccepted quote deadline | Request lock, first quote deadline, no accepted quote; transaction | Previous state -> `CANCELLED` inserted with source event ID. Accepted quote awaiting payment is excluded. |
| `print_requests.status`, `locked_at` and item `production_status` | `PrintRequestProductionService.activateAfterVerifiedPayment` -> `lockForProduction` / `queueForProduction` | Request lock, accepted current quote/pair and supplied success amount; transaction | `QUOTE_ACCEPTED -> IN_QUEUE` inserted; repeat returns current state. **No BE1 verified-outcome caller exists**, so this is not live-verified payment activation. |
| `current_file_version`, `current_spec_version`, `preview_confirmed` | File/Spec version services and `PrintRequest.useFileVersion/useSpecVersion` | CUSTOMER owner lock; Draft or active correction authorization; quote/production lock blocks edits | Immutable File/Spec rows; pointer change resets preview. No status history for same-state edit. |
| `print_quotes.quote_status` | `PrintQuote.accept/supersede/expire`, called by Quote service | Request lock and current quote/version/deadline checks | Quote rows retained. No PrintRequest history for same-state quote record changes. |

Persisted source values are `DRAFT`, `SUBMITTED`, `REQUIRES_REVISION`, `QUOTED`, `QUOTE_ACCEPTED`, `IN_QUEUE`, `CANCELLED`. Quote values are `ISSUED`, `ACCEPTED`, `SUPERSEDED`, `EXPIRED`; item production values include `PENDING`, `QUEUED`. `WAITING_QUOTE_ACCEPTANCE`, `PAYMENT_PENDING` and `QUEUED` are display values derived in `PrintRequestWorkflowPolicy`, not new persisted request values. The already-present persisted `REQUIRES_REVISION`, `QUOTED` and `QUOTE_ACCEPTED` paths are retained for compatibility with current services and history. The 48-table status constraints must still be verified against disposable PostgreSQL.

`PrintRequestWorkflowPolicy` now supplies the shared edit/cancel guards used by File, Spec and State services. Each mutation still checks owner/role and persisted state after locking; `allowedActions` is only a read model. Staff review approval is bound to the exact current File/Spec pair. A historical approval cannot authorize a newer version. Status history is append-only; review actions without a lifecycle transition use Technical Review and audit records.

No duplicate status writer was found outside these BE2 paths, but Quote expiration has both request-time and explicit worker entry points. Their shared request lock prevents concurrent cancellation/replay. Payment success/failure/expiry races remain an integration gap because BE1 has no approved BE2 outcome handoff in this source.
